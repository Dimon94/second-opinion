# 恢复阶梯：先联通，再评议

首次失败先确定层次，再按对应分支向前推进。每个恢复动作都要有执行结果；不把重复问“能否看到工具”当修复。恢复期间关闭业务评议，不关闭诊断。

## 1. 消息是否真正送达

核对目标 Chat URL、连接器选中项、用户消息气泡中的完整指令及本轮 TASK_ID。只有协议头或草稿未发出时，用 paste 补齐并确认发送；这是输入修复，不消耗后续连接恢复机会。挑战已发送时先读取该回合结果；本地授权消费状态不明时重建挑战，不重放旧值。bootstrap 始终留在本地。

完成条件：网页收到完整握手并已完成该回合，能区分实际调用错误、模型自报不可调用和仅未执行。

### OAuth 已交换但未验证 / 授权页过期

Doctor 返回 `probe_oauth` 时按 DOCTOR-HANDOFF 执行一次有界只读探测，再读回 Doctor。`WORKSPACE_BINDING_REQUIRED` 在此只证明认证通过；工作区绑定与实读仍是下一道门。探测仍不通过时报告实际错误，结束本次探测循环，不无限等待或反复配对。

授权页显示 `This authorization request has expired` 时，普通读授权从同一连接器 Reconnect 重新发起；新增 `review.submit` 则按[异步评议](async-review.md)重新进入工具级授权并核验 scopes，生成新配对码并及时交给用户点击 Connect。仅重新填码不能修复旧表单 request_id；授权请求和配对码是两种独立有效期。用户完成后以 Doctor 读回为准。

## 2. 工具发现与调用

若网页说没有 connection_info，打开同一 App ID 的设置页，核对端点和 Actions/schema；查看相关权限是否阻止绑定调用。connection_info 是无副作用的连接证明；真正授权由本地 CLI 执行。

- Actions 包含 connection_info、workspace_info、read_file：回到该会话，明确提供已核实的工具名与参数，要求发现并实际调用 `connection_info({nonce})`；附新 nonce；取得证明后按本地授权握手授权，再做小段实读。模型先前的否定回答不能替代这个尝试。
- Actions 缺失，或设置与会话仍不一致：若 UI 提供该连接器的工具元数据 Refresh，刷新一次并读回 Actions，再刷新会话、重新选择同一连接器，实际重试握手。Refresh 不是 Reconnect；遇到新权限、OAuth 或安全确认时按当前批准规则交给用户。
- 错误证明 token 已过期、已消费或当前未绑定：从真实宿主与 cwd 生成新 bootstrap，在目标会话重新握手一次。
- workspaceId 不匹配：停止材料读取，核对 cwd、本地 ID 和实际会话，纠正错误目标后重新授权绑定；不能把远端错误 ID 改成期望值来通过。
- `SESSION_ALREADY_BOUND`：当前网页会话已有其他宿主或工作区绑定。保留它，不替对方 unbind；回到当前宿主独立拥有的 URL，没有则新建自己的会话并重新握手。此错误与 token 过期不同，反复 mint 到同一错误目标不会修复。
- 清理范围：`binding unbind` 必须从目标 cwd 执行，服务端按真实宿主和规范化工作区共同筛选。跨工作区验收时清理一侧后，另一侧必须再实读一次；单看 removed 数量不能证明隔离。测试失效恢复仅撤销测试任务自己的绑定，保留 OAuth 与其他工作区。

只依据当前可观察的 schema 引导调用；不伪造工具、不让模型编造调用结果。权限明确拒绝时请求具体所需批准，不降低权限保护、不把授权工具改标只读，也不换模型绕过限制。

完成条件：绑定和实读通过，或已取得失败步骤与明确错误/可见性证据。设置列表与模型自报冲突只能证明不一致，不能单独证明其根因。

## 3. 换一个网页会话继续

仅适用于发送/工具发现/会话状态故障。出现明确安全拒绝时跳到下一节的取证分支，不能用替代会话重试被拒绝调用；经过用户批准的不同授权架构应单独验收，不能宣称旧调用已经修复。
Doctor 可用、已有连接器正确，但原网页会话完成上述恢复仍不能握手时，自动创建至多一个替代 ChatGPT 网页会话，保留指定 Pro 模式和同一连接器。不是新建 Codex 任务、不是新建连接器。
保留原 URL 和脱敏失败记录；新会话使用新 bootstrap，重新走完整握手。新会话通过后才更新保存的 URL 并继续用户原问题。分叉产生的新宿主始终使用新宿主真实身份，不复制旧任务 token 或强制认领旧 checkpoint。

完成条件：替代会话绑定实读通过，或也得到可复现的失败证据；不会无限创建会话。

## 4. 何时真正暂停

### 用户授权后的安全拒绝

`Allow once` 批准与工具执行成功分开验收。若回合报告 `blocked by OpenAI's safety checks`，停止重复提交该调用，继续以下只读诊断，而不是立刻让用户重分叉或重复授权：

1. 保存会话 URL、TASK_ID、时间、工具名和脱敏错误。展开可见工具详情，区分原始错误与模型转述；界面没有原始载荷就记录缺失。
2. 使用当前 CLI 的 `logs --help`、`logs -w <project-root>` 查看相关时段的脱敏日志。查是否有该请求的接收、绑定结果或拒绝原因；仅有启动日志或没有匹配记录不证明请求未到达。
3. 有服务端错误码时按该错误定位；只有平台拒绝描述时保持原因 Unknown，不猜测为 token 过期、工具标记或提示词问题。
4. 若缺请求级观测，提出最小诊断变更并取得所需部署授权：只记录时间、非敏感关联 ID、工具名、到达阶段和结果码；不记录请求体、bootstrap、binding_token、OAuth 或文件内容。新增日志必须验证脱敏并安排移除。需要平台原始拒绝详情时明确索取诊断 ID/支持信息。

完成条件：已确认可修复原因，或准确指出缺少哪一层证据及取得它所需的具体动作。没有真实新会话的绑定、实读和评议成功记录，就不能宣布链路修复。Skill 格式校验、服务端测试或历史成功均不能代替这一验收。

只有需要登录/MFA/CAPTCHA、授权/权限扩展、删除重建或部署变更，或以上适用的安全恢复分支已走完仍失败时，才结束当前恢复。基础设施错误按 Doctor 契约处理；Skill 不授予修改服务端或安全策略的权限。
报告具体失败层、已执行动作及结果、未执行动作及原因、下一项最小必要动作。若只是外部平台故障，明确是平台阻塞，别伪装成等待用户作业务决定。
结束时按主 Skill 清理临时绑定，保留可恢复现场。不能把“未绑定”本身作为尚未尝试绑定或恢复就退出的理由。
