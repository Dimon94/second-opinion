# 四宿主实测

用户明确授权新建 Codex 任务后，用任务管理创建 A、A′、B、B′ 四个真实宿主。A/A′ 使用同一规范化项目根，B/B′ 使用另一个根；自动创建的不同 worktree 不算同一工作区。

验收实际项目文件夹时，从 list_projects 解析项目，按用户指定使用原项目的 local 环境创建任务。各宿主首次终端调用不覆盖 workdir，记录初始 pwd、真实 CODEX_THREAD_ID、Git root 与 workspaceId；默认目录不符先报告，不靠 cd 掩盖。projectless 控制任务指定 cwd 只能证明路由，不能替代项目宿主验收。

1. 每个任务自行取得真实 CODEX_THREAD_ID，读取当前 Skill，创建自己的 Pro/Chat、TASK_ID、挑战与绑定。协调者只接收脱敏结果，不转发凭据。四路分别完成身份实读和第二轮读取，保存并读回自己的 session，保留绑定以等待协调验收。
   完成条件：四个真实宿主、两个 workspaceId、四个不同 Chat URL；每路文件内容与分配项目一致，轮次与自己的消息匹配。文件夹验收包括根目录文件及一个非敏感子目录文件：网页只收到相对路径和行范围，返回后再与本地内容比较，不预先提供期望内容。有服务端只读观测时再核验绑定数量和远端 session 不同；哈希可用于比较，凭据不输出。
2. 只让 A 从自己的 cwd 解绑。A′、B、B′ 刷新原 Chat、重读本地 session，用原绑定实际读取身份和小段文件，不重新绑定。
   完成条件：A 清理数量符合预期；另三路均实读成功。仅看清理数量不能证明其他任务未受影响。
3. A 在原 Chat 用旧令牌确认 WORKSPACE_BINDING_REQUIRED，再按主流程生成新挑战、重新授权和实读，保留原 URL/TASK_ID，递增轮次。
   完成条件：旧绑定失效和新绑定恢复分别有证据；不以重置共享 OAuth 代替单任务恢复。
4. 协调验收完再让各任务从自己的 cwd 清理绑定、保存 DONE 并读回，保留结果 Chat 和脱敏记录。用户任务保留，除非另有归档授权。
   完成条件：四路清理有返回值、状态和 URL 可恢复；记录真实通过范围。四宿主读通不是跨令牌、重放、过期、服务重启等所有安全测试均通过，也不等于独立评议达成共识。

协调者使用 wait_threads 等待状态变化；需要阶段证据时读取完成回复。普通执行任务不为测试自行创建更多任务。
