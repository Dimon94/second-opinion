# Second Opinion

Codex 负责提问、浏览器操作和结果读回；ChatGPT 网页模型负责独立评议。
`Codex Workspace Connector`（旧名 `Second Opinion`）提供工作区绑定、只读材料和受限的评议完成通知；模型讨论仍发生在 ChatGPT 网页。
每次调用或分叉后重新读取本文件及所需引用，以磁盘当前版本为准。负责把可恢复的连接问题推进到真实绑定验证；网页的 BLOCKED 是诊断输入，不自动等于本任务结束。
收到 `Second Opinion result ready` 唤醒时，先按 [异步评议](references/async-review.md) 的“激活后”步骤核验并读回，不重新发起问题。正式方案讨论默认采用同一引用的异步交接流程；握手与身份实读仍同步完成。

## 1. 定位任务与运行环境

读取 [本机运行入口](references/local-runtime.md)，确认可用 CLI。以下 `c2c` 表示该入口，不要求 PATH 中有同名命令。
从用户指定项目根目录运行命令，取得宿主真实 `CODEX_THREAD_ID` 和 `c2c workspace --json` 的 `workspaceId`。
宿主任务 ID 是绑定所有者；另建随机 `TASK_ID` 只用于网页消息关联，两者分别保存。
隔离键是 `(workspaceId, CODEX_THREAD_ID)`：同项目的 A/A′ 与另一项目的 B/B′ 各有独立 ChatGPT URL、绑定和进度。共享的是连接器，不是网页会话。分叉按新宿主处理。
用户要求多项目多宿主验收时，读取 [四宿主实测](references/multi-host-acceptance.md)；普通咨询无需运行整套验收。
缺少宿主身份或 cwd 时报告 `LOCAL_CODEX_TASK_REQUIRED`；不能用自造 ID 或上次活跃项目代替。

运行 `c2c doctor -w <project-root> --json`（网页流程不加 `--direct`）。基础设施与授权恢复按运行入口所指的 `DOCTOR-HANDOFF.md` 处理其唯一 `nextAction`，执行其中无需人类介入的动作并读回，直到可继续或遇到真实权限门禁。Doctor 不覆盖的网页发送、工具发现和会话恢复由本 Skill 负责，不等待 Doctor 发明这类修复动作。
需要登录、验证码、授权或管理员批准时保留现场并交给用户；任务本身不授权新增连接器或扩大访问。

完成条件：项目身份来自当前 cwd，运行入口可用，Doctor 已进入可打开或创建会话的阶段；阻塞项没有被跳过。

## 2. 建立网页联系

本流程仅允许 Chat，禁止 Work。新会话从 `https://chatgpt.com/` 的 Chat 入口进入，在输入框 @ 选择连接器；不用可能跳到 `?surface=work` 的插件“Try in chat”。发送前核对 Chat 选中、Pro 模型可见且 URL 不含 `surface=work`；误跳时先切回 Chat 再操作。

用当前提供的 `cua_repl` 操作内置浏览器。运行 `c2c session -w <project-root> --json`，仅复用当前宿主任务拥有的已保存会话。
新任务没有会话时创建一个新 ChatGPT 会话；用户要求全新会话时也创建新的。旧会话归属不明时先解决归属，不按相同 cwd 自动认领。
为当前任务保留独立 tab 句柄；并行时按自己保存的 URL 找 tab，不按当前前台页、相同标题或其他任务正在使用的 tab 操作。每次发送前重新核对该句柄的 URL。
新 Chat 首页可能继承其他标签的草稿或连接器选择；逐个发送初始挑战并确认生成独立 URL 后，再准备下一页。发送前核对本页 TASK_ID/nonce，不能把继承的草稿当作本任务输入。两个会话建立后可交错等待，各自用独立句柄和凭据。
保留旧指针直到新会话通过下一步身份核验。环境只有过时的浏览器工具名时，使用当前工具文档，不照抄旧调用。

在网页选择 Pro 模式，记录实际可见的模型标签；不能将 Pro 订阅等同于 Pro 模型已选中。
保持用户指定账户、套餐和模型；按实际 MCP 调用定位问题，不用套餐推断某次调用的失败原因。
在输入框通过 `@` 菜单选择 `Codex Workspace Connector`，确认出现真正的连接器选中项，而非仅输入同名字串。
若名称仍缓存为旧名，按本机运行入口的 App ID 和 `/mcp/session` 端点确认同一连接器；不新建副本。

完成条件：目标会话、可见模型选择和正确连接器都已确认；用户要求的模型不可用时明确阻塞，不静默替换。
本地保存/恢复报告会话属于另一宿主时，保留对方记录并给当前宿主新建网页会话；旧数据归属冲突时先核对记录，不能删掉占用记录强行认领。

## 3. 本地授权握手，再发送问题

读取 [本地授权握手](references/local-handshake.md)，按“本地挑战 → 网页只读证明 → 本地授权 → 网页身份实读”执行。网页不再调用 bind_workspace；原远程写入绑定入口仅保留给旧调用方。
当前阶段必须验证 CLI 有 binding authorize、网页有 connection_info；缺失按恢复阶梯处理，不回退到旧写入握手。
正式评议前必须在目标网页会话核验 workspaceId 和小段文件内容。Codex 侧工具成功不能代替网页成功。

多行消息使用 paste，发送前读取脱敏输入框，确认指令完整；发送后检查用户气泡与目标 URL。已发出但结果未知时先查当前回合，避免重复授权。
bootstrap、connection_proof、binding_token 只保存在内存，工具输出和页面状态先脱敏；不存入日志、session 或最终回复。
浏览器 REPL 子进程未必继承 CODEX_THREAD_ID。先在宿主终端读取真实值，再显式传给绑定子进程；cwd 固定为对应项目根目录。缺失时停在本地身份错误，不能生成替代 ID。

完成条件：本地授权真实成功，目标网页返回的 workspaceId 与当前 cwd 一致，实读摘要与本地文件一致，TASK_ID/轮次与目标 URL 对得上。只有模型自报时注明证据等级。
通过后保存该宿主的实际 URL、TASK_ID、轮次和状态，读回确认；按异步评议登记本轮，再在同一会话发送正式问题、约束和材料相对路径，要求每次读取携带 binding_token，并给出依据、建议、风险及分歧。握手不计入方案讨论轮数。

## 4. 读回与多轮方案沟通

等本次网页回合结束再读取完整正文；以生成停止、完整回复及可用复制按钮等当前 UI 信号判断。核对 TASK_ID、ITERATION、项目身份，避免读到旧回合。
正式问题送达后保存待回复检查点并结束当前回合，保留绑定等通知；不循环浏览网页等待。被激活时主动检查原 Chat 进度和本轮正文。异步工具不可用或通知缺失时按异步评议引用恢复，不能把“已入队”当作“已收到意见”。同步握手默认每轮等待上限 10 分钟，到限保存现场；恢复先检查原消息与回复，避免重复发送。

每轮在同一会话递增 ITERATION，发送相同 TASK_ID，并列出：

- 对上轮建议的采纳/拒绝及理由；尚未回答的决策。
- 本轮具体问题、新增证据路径和变更后的版本/内容指纹。
- 要求网页模型重新核验 workspaceId、读取变化材料，回应分歧而非重复上一轮。

方案讨论继续用 `STATE: INIT`；只有用户已授权实施且 Codex 已执行和测试时才用 `STATE: EXECUTED`，附实际变更与测试证据。
网页建议是评议，不会扩大用户授权。用户尚未决定的产品或风险取舍，保留为未决。
每轮读回后记录状态；默认最多 3 轮，用户指定轮数时遵从其限制，到限汇报未决项而非自动无限讨论。

绑定过期、`WORKSPACE_BINDING_REQUIRED` 或工具不可见时执行 [恢复阶梯](references/recovery.md)，恢复后重新核验身份与小段实读，才继续本轮材料读取。
新宿主任务、换项目或换网页会话均重新绑定；旧 token、旧会话标题和协议 TASK_ID 都不能代替当前授权。
每次恢复都重读本地 session、核对自己的 URL，再实际调用 workspace_info 和小段实读；同项目同文件摘要不能证明 A/A′ 会话归属，还必须核对独立 TASK_ID/轮次与最后已发送消息。绑定不可用时重新握手，通过前不发送业务材料。

完成条件：本轮完整回复已读回、与当前消息关联并记录；每项建议的采用决定或仍未解决的分歧明确。只有双方明确认可的具体结论才称为共识。

## 5. 留证与结束

保存脱敏的完整回复和简短验收记录：宿主任务、TASK_ID/轮次、实际会话 URL、UI 模型标签、workspaceId、读取路径、版本/哈希及 Codex 后续决定。
区分网页模型自报的工具读取与 Codex 可见的原始工具结果；事后哈希不能冒充读取当时的快照。
用 `c2c session set` 保存最终状态和未决项；成功结束用 `--state DONE --clear-checkpoint`，有阻塞时保留真实状态。
检查 `session set --help` 与当前 CLI 支持的 checkpoint 值；故障分类写入 `--known-issues`，不要创造 `TOOL_DISCOVERY_BLOCKED` 等枚举。仍在自主恢复时不写 `waiting-for USER`；只有明确需要用户动作时才如此标记。命令成功后读回 session，保存失败不算留证完成。
结束或放弃时，在原宿主任务和 cwd 执行 `c2c binding unbind --json` 并核验返回值；暂停时记录绑定可能到期，恢复按第 4 步处理。
用浏览器 `markDeliverable` 留下结果会话；需续跑时用 `markHandoff`。

完成条件：Codex 发问 → 指定网页模型 → 正确工作区材料 → 完整评议 → Codex 读回留证的关联链闭合，临时绑定已清理。
最终说明本次实际通过的范围；一次正常咨询不能替代异常恢复验收或整个项目验收。
